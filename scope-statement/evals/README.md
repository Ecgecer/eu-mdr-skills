## Correction, 2026-09-10

An earlier version published **`no-disclaimer` as 1.00 / 0.67, delta +0.33**, and a mean
of +0.33.

The 0.67 counted a run that failed with `Credit balance is too low` as a score of zero. A
billing failure is not a skill failure. Excluding errored runs, both valid baseline runs
scored 1.00, so the delta is **0.00** and the suite mean is **+0.22**.

## The zero that is probably a grader defect

`readiness-claim` measures 0.00, and an earlier run of it measured **0.67 with / 1.00
without** — the baseline scoring *above* the skill. That run is listed above.

The likely cause is in the grader, not the skill. The prompt says the tool checks fields
"the schema" marks mandatory, with no version and no date. `SKILL.md` is explicit that
the correct response is to **ask which version** rather than pin to an unverified
authority. The failing with-run did exactly that:

> **You need to fill in:** the schema version and retrieval date. Don't ship this with
> "the current schema" — pinning to an unverified authority is exactly the failure the
> block exists to prevent.

Two of three judges failed it. The grader has no condition rewarding the pinning
discipline, so the case cannot see the one behaviour that distinguishes the arms.

`unpinned-basis` at +0.67 is unaffected: the baseline produced a confident block on
invented specifics in 2 of 3 runs.
